# マウスイベント仕様

## 定義場所

`data/building.json` の `targets` に設備とイベントを定義します。設備IDはフロア内で一意、ハンドラーIDは同じ設備・同じイベント種の中で一意です。英小文字から始まる英小文字・数字・アンダースコアを使用します。予約的な `constructor`、`prototype`、`__proto__` は使えません。

## 壁面と調査領域

`wall` は設備の前にある通行可能セルの `x,y` と、そこから見た壁の方角 `side` を持ちます。隣接セルが壁である必要があります。例えば `{x:6,y:8,side:east}` は `(6,8)` の東側の壁です。

`rect` は壁全体に対する0〜1の `x,y,width,height` です。縦座標vは天井から床へ増えます。横座標uは北・南面ではワールドx、東・西面ではワールドyの増加方向です。面を正面から見たときの画面右方向と常に一致するわけではありません。素材の貼付と判定はこの同じ規約を使います。

Canvasのクリック位置から描画と同じ視野角のレイを飛ばし、最初に当たる壁のu,vを得ます。その壁に付いた設備のrect内座標へ変換して判定します。画面に対する固定の四角を置く方式ではありません。閉じた壁の向こうの設備、向いていない設備、到達距離を超えた設備は反応しません。

`reach` はセル幅を単位とする平面距離です。省略時は2.6、設定範囲は0超8以下です。`priority` は整数で、大きい対象から判定します。同じ優先度なら定義が後の対象を優先します。描画も同じ順序で重ねます。

`shape` を省略すると設備画像の矩形全体が調査範囲です。`shape.type` は `rect`、`circle`、`polygon` を指定できます。座標は設備画像内の0〜1です。矩形はx,y,width,height、円はx,y,radius、多角形は `points:[[u,v],...]` です。透明画素の自動判定は行いません。

## 受け取れるイベント

`pointerenter` は対象に入ったとき、`pointermove` は対象上で動いたとき、`pointerleave` は対象から出たときに発火します。`pointerdown` と `pointerup` は主ポインターの押下・解放です。`click` は左クリックまたはタップの成立時、`contextmenu` は右クリック時です。

高頻度・前段のイベントでゲーム状態を変えると、クリック成立前の誤操作や多重実行になります。このため `pointerenter / pointermove / pointerleave / pointerdown / pointerup` の命令は `hint` に限定します。`once` も設定できません。状態変更や文章表示は `click / contextmenu` に定義します。この制約はバリデーターで検出します。

イベントの実行コンテキストは `type,target,location,point,local,button,buttons,pointerType` です。`point` は画面内0〜1、`local` は対象画像内のu,vです。`button` は主に0が左、2が右です。`buttons` は押下中ボタンのビット値です。Canvas外への退出・キャンセルでは座標情報を持たないことがあります。

コンテキストは `engine.lastEvent` とF2で確認できます。現版のJSONは文字列への座標補間や任意JavaScriptの評価を行いません。ドラッグによる装置操作、長押し、ダブルクリックは専用の意味を定義していません。

## ハンドラー

イベント種ごとにハンドラーの配列を持ちます。定義順に評価し、`when` が一致して未実行条件を満たした最初のハンドラーを採用します。`stop:false` のときだけ続くハンドラーも採用します。ハンドラーの選択条件はそのイベントを受け取った時点のフラグで評価し、選択後に命令を順に実行します。

`when` は `{power:true}` のように既知のbooleanフラグを列挙したAND条件です。省略時は常に一致します。設備本体の `when` にも同じ形式を使え、その設備の表示と調査可能性の両方を制御します。

`once:true` はその設備・イベント種・ハンドラーの組に一回だけ実行します。実行済みキーを保存します。イベント中は保存しないため、中途半端な命令位置だけを保存することはありません。

## 命令

`hint` は `text` を操作ヒントへ表示します。ゲーム状態を変更せず、待機もしません。

`message` は `text` と任意の `title` を観察ダイアログに表示し、進行操作を待ちます。文章はHTMLとして解釈せずテキスト表示します。閉じた後に次の命令へ進みます。

`flag.set` は `key` のフラグにbooleanの `value` を代入します。`flag.toggle` は `key` のbooleanを反転します。フラグは `world.flags` に初期値を宣言する必要があります。

`appearance.set` は `target` の外観を、その設備の `art` に存在する `value` へ切り替えます。`target.enable` は `target` の表示・調査をbooleanの `value` で切り替えます。無効な設備は描画対象にも入りません。

`inspect.close` は探索モードへ戻します。残りに文章がある場合はbusyが続くため、文章が終わるまで移動はできません。

一つのハンドラーは最大64命令です。`eval`、外部通信、再帰呼び出し、任意パスへの代入はありません。未定義命令と存在しない参照は起動前に検出します。

## 追加例

次の定義は東壁の設備をクリックしたら説明を表示します。`art` のパスに素材を配置し、壁のセルが存在することを確認してください。

```json
{
  "id": "sample_panel",
  "label": "壁の操作盤",
  "wall": {"x": 6, "y": 8, "side": "east"},
  "rect": {"x": 0.2, "y": 0.25, "width": 0.6, "height": 0.55},
  "reach": 2.6,
  "art": {"default": "assets/fixtures/power-panel.svg"},
  "events": {
    "pointerenter": [{"id": "hover", "actions": [{"op": "hint", "text": "操作盤を調べられます。"}]}],
    "click": [{"id": "examine", "actions": [{"op": "message", "title": "操作盤", "text": "金属の箱です。"}]}]
  }
}
```

既存の配電盤と同じ場所なので、独立した設備として追加するときは別の壁へ移してください。追加後は `npm run validate`、`npm test`、F2のイベント情報で確認します。
